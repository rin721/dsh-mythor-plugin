# 认知基础与设计推导

## 小说机制

goal.md 的核心并非「管理人物、生成章节」，而是稳定规则中的人物因欲望受到阻碍，做出选择并承担后果。后果改变世界、关系、资源或认知，产生下一轮行动的条件。设定为行动提供条件，正文则选择以何种顺序、视角和信息量呈现行动。

因此，一个场景的创作对象包括行动前的处境、人物目标、阻碍、选择、代价和行动后的变化。工具可以整理这些信息、指出缺失与矛盾，但不能以固定公式裁决文学质量。过渡、氛围、静态描写和开放结局都允许存在。

## 作者实际上做什么

| 作者行为 | 作者判断 | 数据与系统责任 |
| --- | --- | --- |
| 提出底层规则 | 什么变化值得推演 | 保存规则、例外、适用对象；推演结果是候选 |
| 塑造人物 | 为什么想要、害怕什么、如何取舍 | 目标、内部需求、动机、底线及其演变 |
| 制造冲突 | 哪种阻碍能迫使选择 | 冲突连接主体、目标、阻力与风险 |
| 规划行动 | 哪种选择带来何种后果 | 候选事件、因果关联、前置条件 |
| 安排叙述 | 何时让谁知道什么 | 世界时间、正文顺序、认知和揭露分离 |
| 写作与改写 | 这个场景改变了什么 | 正文修订与有来源的状态变化 |
| 检查与回溯 | 旧设定变化影响哪些后文 | 依赖分析、失效标记、修复任务、历史 |

## 设计不变量

1. 同一对象在工具、存储、Agent 和 UI 中使用同一 ID 与概念。
2. 正文中的一句话不自动成为世界事实；对白、误解和不可靠叙述必须保留认知主体。
3. 叙述顺序不是世界时间。历史版本也不是故事中的时间。
4. 模型生成内容先是候选，正式提交由可验证的领域服务负责。
5. 上下文是有范围、有版本的检索结果；聊天记录不代替小说数据库。
6. 检查器可以返回未知；没有发现冲突不等于证明文学合理。

## 术语

- Harness Workspace：宿主管理的项目目录与会话归属；一个工作区承载一部小说。
- NovelState：Mythor 在当前工作区维护的小说身份、作品标题、正式修订、故事种子和创作状态。
- Canon：作者接受的正式记录；不是正文句子的集合。
- Entity：可引用的创作对象；类型词汇见领域模型。
- Assertion：主体关于某件事的断言，可为事实、计划或假设。
- Knowledge：人物的认知；允许误信，与真实断言分别保存。
- Revelation：读者在特定叙述位置获得的信息。
- Scene：写作与状态变化的主要组织单元，不等同于地点。
- ChangeSet：一个可审阅、可校验、可原子提交的修改集合。
- Revision：作者编辑历史中的版本；不表示世界时间。
- SourceRef：指向特定正文修订和文本区间的证据。
- ContextPack：某阶段实际使用的检索内容及其版本和来源。

产品名称统一为 Mythor。goal.md 中的 Mythos 是概念来源，不另建兼容业务词汇。
