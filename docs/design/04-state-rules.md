# 状态、规则与一致性

## 正交状态

- informationStatus：fact / plan / hypothesis。fact 仅表示作者确认其属于世界事实。
- editorialStatus：draft / pending / accepted / retired。草稿和待审阅修改保留在候选集合；接受才更新正式记录。
- WorkflowRun：pending / running / waiting_review / completed / cancelled / failed。
- ChangeSet：pending / committed / rejected。检查结果单独记录其输入版本，不能重复使用过期结果。

人物误信通过 knowledge 记录表达，不能因为人物相信就变成 fact。草稿里新出现的人名不自动创建正式人物。

## 提交协议

1. 校验外部输入、项目与对象身份、来源范围和操作大小。
2. 读取预期项目版本，构造修改后的候选快照。
3. 在候选快照上检查引用、来源、时间和规则；因此同一批创建的对象可以互相引用。
4. 检查提交者为作者、具有协调凭据的内部 Host 策略，或拥有有效范围授权的模型。模型正式事实/正文仍必须经协调，授权不替代检查。模型和浏览器不得通过参数伪装策略身份。
5. BEGIN IMMEDIATE 后再次核对版本和幂等键，将正文、对象、关系、失效标记、历史及项目版本一起提交。
6. 索引与数据同事务更新，COMMIT 成功后返回新修订；响应丢失后使用同一幂等键返回原结果。首版 UI 在操作后刷新，跨会话变化使用刷新按钮读取；实时修订订阅是后续扩展。

授权与 Harness 工具审批是两层不同约束：前者表达创作意图，后者保护运行环境，两者均不能被绕过。

## 校验分类

结构硬错误：悬空引用、跨项目引用、重复身份、无效来源范围、无效修订、时间范围反转、因果/先后循环。必须修复才能提交。

创作规则可为 hard 或 advisory。首版确定性规则使用有界 predicate（required_attribute、forbidden_relation、attribute_equals），不执行用户提供的任意代码。自然语言规则只产生人工/Agent 检查项，不能假装已经机器证明。

诊断包含 code、severity、message、entityIds、sourceRefs、suggestion。严重程度为 error / warning / unknown；unknown 需要人工判断，授权自动提交遇到 unknown 或未处理 warning 时停在审阅阶段。

## 修订影响与回溯

修改正文后，引用旧正文的提取记录标记 stale，并在同一事务创建复查任务；修改对象时遍历关系和来源依赖，返回受影响对象。首版只自动派生正文来源复查任务，规则变更的完整依赖重检调度留作扩展。读取上下文默认排除 stale 派生记录，同时报告缺口。

撤销不是删除历史：从提交逆操作构造新的候选，在当前版本重新检查。若后续提交已改动同一对象，返回冲突并要求重新形成修复方案。禁止未经审阅级联删除关联对象。

## 持久化异常

数据库忙、磁盘失败、取消、版本冲突、模型输出错误各有稳定错误码。事务失败不得推进内存版本。启动时将未完成的 running 任务恢复为可继续的 pending，保留已完成阶段。数据库版本高于软件支持范围时拒绝打开写入；迁移前建立一致备份。

## 创作信息的晋升

表达保存原话；解释允许修正；建议与假设保持未确认。作者决定仅适用于具体范围，候选绑定基线，验证和事务提交后仍保留信息性质：Commit 不等于 Canon。`creative.put/delete` 只允许宿主核验策略或绑定候选哈希的补偿接纳，不能由浏览器或模型直接提交伪造表达。

自然语言确认当前采用保守边界：已呈现的唯一候选、完整明确确认句、真实本会话作者来源、呈现之后的消息、候选哈希和版本未变。偏好、条件句及截取肯定片段不批准修改；歧义回到原生问答。跨会话决定依据保存到项目，旧会话问答窗口不被新会话继承为授权。
