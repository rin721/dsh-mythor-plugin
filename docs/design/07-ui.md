# UI/UX 与关系可视化

## 工作台

Mythor 通过公开 `conversation.view` 注册在“对话”“轨迹”之后，不注册独立 main 页面或顶层面板。0.3 移除输入区启用入口；首条消息前直接表达想法，无标题或模式门槛。重要决定由 Harness 原生问答承接。界面以 Harness [组件目录](https://github.com/deepseek-ai/deepseek-harness/blob/21638c5631/packages/client/ui-primitives/README.zh.md)及[样式规范](https://github.com/deepseek-ai/deepseek-harness/blob/21638c5631/docs/web-styling.zh.md)为准。

## 统一组件适配层

业务页面仅从 `src/client/ui/` 引入通用控件。Harness `0.1.7-rc.2` 的公开 Button、Input、Checkbox、Tag、Pill、StateDot、Modal、DisclosureRow、JsonTree、DiffBlock、Toast 优先复用，Menu、Tooltip 和分段组件保持统一出口。官方组件不复制源码、不覆盖内部元素外观。

缺少的 Select 使用 Radix Select，并由官方 Button 提供触发器、MenuSurface 提供菜单材质；空选择编码仅存在于视图层，回调仍返回领域原值。TextArea 使用受控 React 封装，NumberField 复用官方 Input，未知数字保持空值。FilePicker 使用官方 Button，封装文件输入和同一文件重复选择。Field、FormActions、Panel、EmptyState、LoadingState、ErrorState、Feedback 统一组合布局与状态反馈。展开内容组合官方 DisclosureRow 与 Radix Collapsible。业务页面不直接使用裸表单控件、不导入 Radix；适配层内部允许必要 DOM。

适配层只持有展示与交互状态，不调用应用服务，不存储领域数据。官方原语通过 Harness 共享模块加载，Radix 按需打入客户端；样式使用 CSS Modules、clsx 与宿主主题令牌。CSS 随客户端产物内嵌，工作台挂载时注册，卸载时移除，也覆盖 body portal 内容。用户明确要求以无样式组件库补齐官方缺项，该取舍见 [ADR 0002](../adr/0002-harness-ui.md)。

一级只保留创作、正文、故事资料。领域能力按上下文或更多进入，不保留十页数量作为产品约束；没有第二层项目、启用表单、标题门槛或独立 Composer。

创作页使用同一个主创作区与辅助事项区骨架：空状态引导表达；探索中展示带性质和原话依据的理解及最多两个问题；创作中展示实际任务与接受规划；长期创作显示最近推进并按需深入资料。窄屏优先事项，宽屏左右排列。正式变化区区分事实、规划、正文和创作记录。

正文沿用编辑与修订能力。故事资料下深入人物与世界、故事发展、双时间线及关联图谱。检查、候选审阅、历史、任务仍沿用同一领域服务；维护入口包含旧版迁移、恢复和备份。数字统计不再主导首页。

错误提供可读结果、重试和折叠诊断，不直接展示 gateway/transport。背景刷新不清空输入或折叠诊断。Composer 插入使用宿主快照与 insertText；失败时保留文本，不覆盖草稿。全部新增核心文案有中英字典，领域内容不翻译。

workspace.progress 是只读投影。正式内容在 Project 共享；正文未提交编辑、浏览页和焦点使用 session.state/session.save。无工作区保持安静的原生选择说明；未建立小说不写 .mythor。

## 图谱投影

人物关系图、参与事件图、事件地点图、组织结构、因果剧情图、行动路线和故事线交叉图使用同一 entities/relations。行动路线按世界时间连接地点，不伪造地图坐标。故事线交叉通过共享事件/场景表达。

操作：选择类型和时间范围 → 搜索焦点 → 展开一层邻域 → 聚焦/追踪路径 → 查看来源 → 发起编辑。节点移动只保存视图布局，不改变领域。建立/移除关系均产生 ChangeSet。显示总结果与已加载数量，不能把截断图误称为全图。

## 编辑与可访问性

正文使用 CodeMirror；实体表单含公共字段及类型特有属性。保存草稿与接受正式变更分开。输入错误就地显示，冲突保留用户输入并提供比较。导入先预览章节拆分结果，再提取候选事实。审阅与历史的结构化操作使用 JsonTree，候选正文前后比较使用 DiffBlock；差异只是一种呈现，不重新计算提交基线。持续错误使用可读反馈与明确关闭动作，操作成功使用宿主 Toast。

所有图形提供列表对应视图，键盘可聚焦对象，详情有可读名称。颜色之外用图标/文字区分状态。支持深浅主题、窄屏折叠、模态焦点约束、Escape 关闭和加载/空白/失败状态。弹窗键盘行为由官方 Modal 管理，内部选择器由 Radix 管理；不使用 React autoFocus 或手写焦点循环。Cytoscape 读取实际宿主颜色并在主题变化时更新，CodeMirror 使用继承的主题变量。离线专用恢复交互属于待扩展设计。

## 验证

以上是持续演进的交互设计。0.1.0 的时间线使用排序列表，未知时间排在末尾；图谱按单一时间点过滤，节点拖动尚不持久化布局。检查页提供诊断列表，组合筛选和自动定位仍待扩展；正文修订差异在候选审阅中查看。统一 UI 后的明暗主题、窄屏、页面及弹窗验证见 [实施记录](../implementation/status.md)。

以真实安装后的 Harness 页面作为 UI 验证对象。验证导航、主题、编辑、导入、审阅、图谱聚焦、任务取消与恢复，并检查浏览器报错。独立开发 fixture 只用于确定性测试，不代替宿主集成验证。
