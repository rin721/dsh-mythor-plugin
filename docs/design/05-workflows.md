# 创作流程与 Agent

## 职责

Coordinator 负责用户意图、任务范围与阶段推进；Planner 提出候选行动及后果；Writer 编写正文；Critic 检查证据和一致性；Keeper 归并对象、来源和变化。它们是可组合职责，不要求同时运行五个 Agent。

Harness 拥有模型请求、会话日志、重试、取消和子 Agent 生命周期。Mythor 只保存创作业务阶段，通过作用域工具和阶段提示引导已有 Agent。任何时候都可查询当前任务，不依赖模型记住上一步。工作台未指定会话时使用 Agents.create，恢复任务使用 Agents.get/resume；命令复用调用者的 Agent。不同创作职责目前由同一个 Harness Agent 分阶段执行。

## 阶段与产物

| 阶段 | 输入 | 产物 | 权限 |
| --- | --- | --- | --- |
| read | 项目、焦点、时间/视角 | ContextPack | 只读 |
| goals | 作者意图、人物目标 | 目标和风险说明 | 保存任务产物 |
| plan | 状态、约束 | 候选行动、场景目标 | 候选 |
| simulate | 候选行动 | 后果、代价、待确认点 | 候选 |
| write | 已选方案、可写信息 | 正文草稿 | 候选 |
| extract | 正文草稿及来源 | 对象、关系、认知变化 | 候选 |
| validate | ChangeSet 和基线 | 确定性检查及 Critic 结果 | 只读/检查 |
| review | 差异、证据、检查 | 作者选择或授权结果 | 作者或有效 grant |
| commit | 已接受候选 | Commit 与新版本 | 领域提交服务 |

plan 流程在 simulate 后进入 review；check 流程以诊断结束，作者通过 task.finish 接受这两类任务产物。import 原文变更与提取任务分离，先接受原文再恢复提取任务。write/revise 使用完整阶段链。阶段输出必须先保存再推进；不能跳过阶段，也不能以一句「完成」代替服务校验或提交。Critic 使用 task.critique 保存带来源的 warning/unknown 建议，changes.validate 将其与确定性检查合并；不把模型意见伪装为确定性硬错误。

## 上下文与记忆

ContextPack 包含 projectId、revision、focus、perspective、time、查询结果、来源和截断说明。检索顺序：固定创作约束 → 焦点对象 → 相关事件与关系 → 人物知识 → 最近正文 → 全文补充。按字符预算裁剪材料，优先保留规则及对象证据；预算不足时明确报告缺口，不能把未加载的规则视为不存在。ID、边界元数据和截断说明计入预算。

长期事实来自项目数据库；阶段工作记忆来自 WorkflowRun；知识材料保留原始来源；经验总结必须带适用条件及支持案例，作为可撤销建议，不自动改动 Canon。首版不依赖 embedding。

## 授权与失败恢复

作者可授权一个任务写入指定对象；扩大范围必须重新授权。创建 grant 的入口仅开放给用户命令和 UI。模型工具只读授权并尝试受限提交。

任务保存基线修订、绑定会话、当前阶段、每阶段产物和错误。取消阻止继续推进和提交；已保存草稿保留。恢复前重新读取当前版本，若正式状态变化则重新校验上下文和变更集，而不是重复提交旧操作。对同一次工具调用重复保存阶段产物保持幂等。

## 场景案例

林烬想取得地图，顾清想判断他是否可信；地点为废弃车站。规划必须同时解释拿到地图和暴露破绽的因果。Writer 写草稿；Keeper 提议地图归属转移、暂时合作和顾清的身份怀疑。怀疑是顾清的 knowledge，不是世界事实。作者接受后，正文与这些变化一次提交；倒叙安排只改变叙述位置，不倒置物品转交时间。
