# 小说创作能力目标核验

核验日期：2026-09-29。基线：`8297597`，Mythor 0.2.0，Harness 0.1.7-rc.2。本轮检查现有实现并增加一项宿主作用域闭环回归，没有修改生产行为。认知依据仍为 [goal.md](../goal.md)，领域语义以 [领域模型](../design/03-domain.md) 为准。

## 结论

当前实现符合“以 Harness 为运行环境，在工作区内维护小说领域状态”的基础方向；尚不能判定已经实现“无创作经验用户从模糊想法持续完成长篇”的完整目标。领域事务闭环已经有自动化证据；渐进引导、长期任务接续与创作阶段的信息边界仍有实现缺口。

## 已核验的基础边界

| 目标 | 证据与范围 |
| --- | --- |
| Harness 管理项目 | `WorkspaceNovels.resolve` 使用 Session cwd 与 WorkspaceRegistry 校验归属；正常路径没有 Mythor catalog 或会话绑定。旧 catalog 仅作为显式迁移来源 |
| Harness 管理 Agent | `src/index.ts` 通过原生 `followup`、`cancel`、Tools、Commands 与 `system-prompt/assemble` 工作；没有独立模型客户端或第二套 Agent Loop |
| 一工作区一小说 | 工作区目录内使用 `.mythor/novel.sqlite`；已有测试验证同工作区共享、不同工作区隔离、未启用不创建数据 |
| 长期小说状态 | 人物、地点、组织、事件、章节、场景、故事线、人物弧、伏笔、断言、知识、揭露与规则共用实体、关系及来源模型；正文修订、候选、历史与任务进入 SQLite |
| 作者拥有正式决策权 | 模型操作与作者操作区分 Actor；模型不能启用小说或签发 grant。ChangeSet 提交执行版本、关系、来源与授权校验 |
| 可恢复领域流程 | 持久化 read/goals/plan/simulate/write/extract/validate/review/commit 阶段及产物；阶段顺序、取消、恢复、冲突与补偿历史已有回归覆盖 |
| UI 使用原生入口 | 使用公开 `conversation.view` 和 `conversation.input.left`，通用控件共用适配层；本轮 UI 边界检查通过。未重做全部真实 Web 人工验收 |

新增 `tests/harness.spec.ts` 闭环用例通过真实 SQLite Worker 与公开 SystemPrompt 服务验证：模型身份提出不完整种子、人物、场景、物品关系和正文 → 正式正文仍为空 → 未授权模型提交失败 → 作者校验并接受 → 同工作区另一会话的上下文出现 revision 1、种子、关系及正文。该用例直接调用应用接口，不能计为真实模型自然语言创作验收。

## 当前实现缺口

| 优先级 | 发现 | 实现依据 | 对目标的影响与修正方向 |
| --- | --- | --- | --- |
| P1 | 普通对话缺少持续的创作方法指导 | `GENERIC_HELP` 仅拼进 `taskMessage`；`installNovelContext` 只添加 ContextPack JSON。工具描述未提供完整操作参数 Schema | 任意自然语言开场不能保证触发渐进追问及结构化保存。应把领域方法、最少追问策略与工具契约注册到当前 Agent 的公开指导扩展中，而非另建对话 Runtime |
| P1 | 启用不会覆盖已存在的其他活跃会话 | `installFor` 只在 `agent/created` 和 Remote `onEnabled` 为指定 Agent 调用 | 同工作区其他已加载 Agent 可以共享数据库，但尚未拥有工具或上下文钩子。应通过 Harness 的公开 Agent 生命周期/作用域机制补装，并验证恢复与卸载 |
| P1 | 写作阶段持续注入作者全知上下文 | `installNovelContext` 固定 `perspective: 'author'`，不读取当前写作任务的视角和叙述位置 | 工具额外返回受限上下文不能撤回已经注入的秘密。应让写作阶段组装遵守人物知识/读者揭露范围，同时保留规划阶段的作者视角 |
| P1 | 初始化没有可恢复的等待补充流程 | WorkflowRun 没有初始化类型或 `waiting_user`；种子表直接形成 ChangeSet，未创建初始化任务；“从想法开始”仅向对话输入区放入提示 | 有效片段可以保存候选，但缺少待问问题、作者偏好、已答内容和下一步的持久接续。应保存领域引导进度，并复用 Harness 原生用户输入机制 |
| P1 | 新会话无法仅凭上下文准确恢复旧任务 | ContextPack 的 pending tasks 是不带 ID 的字符串；模型工具没有任务列表/详情查询动作 | 恢复需要从 UI 或既有聊天找到 ID。应提供有预算的任务身份、检查点及按需读取契约，复用现有任务服务 |
| P2 | 导入材料分类未持久化 | `importText` 接收 `materialKind`，但 DocumentSchema 和提取任务不保存类别；类别仅在导入返回值中出现 | 重启后不能可靠区分大纲、世界观、笔记与正文。应在来源/材料领域记录保存类别、文档引用与分批提取检查点 |
| P2 | 子 Agent 继承小说作用域尚未实现明确路径 | `resolve` 仅检查当前 Agent ID 是否在 WorkspaceRegistry.sessionIds，没有父会话身份解析 | 不能据此宣称所有子 Agent 都可访问父项目小说；需要在 Harness 公共谱系机制上验证，并拒绝工作目录不符的继承 |

这些结论来自本轮源码检查；其中未安装扩展、固定作者视角、缺失状态与材料字段是代码事实。子 Agent 的最终表现依赖宿主登记行为，仍需真实集成验证，不能直接认定全部子 Agent 都失败。

## 未计入已通过项

本轮没有配置或调用真实模型，没有重新操作真实 Web 的十页与全部弹窗，也没有执行跨平台、移动目录或长篇规模性能验收。测试通过证明已覆盖的领域与适配行为，不能证明模型主动引导、文学质量、长篇规划质量或整个自然语言循环已经达标。

下一轮应优先补齐上述 P1，再用可控模型走完整 Harness Agent Loop，观察工具参数、追问、候选、审阅与下一轮上下文；最后补真实模型和长篇材料验收。验证结果与需求 M05、M09、M10、M13、M15、M16 关联，需求追溯表不把这些目标改标为完成。
